# bug_0248 — The SVG work bound undercharges short `<text>` elements

| field | value |
|---|---|
| ID | bug_0248 |
| Status | **fixed** (the commit after `0cd8083`) |
| Severity | medium (DoS: bounded CPU and memory inside the work budget) |
| Component | `src/svg_bounds.rs` (text work charge) |
| Discovered by | remeasuring `MAX_SVG_WORK` on usvg 0.50 with a real font |
| Discovery agent | Claude Code session, `claude-opus-5-5` |
| Commit at discovery | `0cd8083` |
| Date | 2026-11-23 |

## Symptoms

Documents of many one-letter `<text>` elements passed the work check and
took far longer and more memory than ADR 0040's ~60 ns per unit allows. On
usvg 0.50, 200,000 stroked one-letter texts used 81% of the budget and
converted for 1.04 s at a 730 MB process peak (153 ns per unit).

## Root cause

`Graph::text_work` charged a `<text>` for its bytes, characters and spans.
The tree and glyph paths usvg builds for each element, whatever its length,
were not charged.

## Fix

Each `<text>` instance costs `TEXT_ELEMENT_WORK` = 256 more units.

Remeasured on usvg 0.50, release, with Bevy's default font:

- 28,000 stroked one-letter texts (97% of the budget) convert in 147 ms at
  a 120 MB process peak.
- The slowest accepted input measured is still 2,000 one-character
  `<tspan>`s (98%), at 0.40–0.51 s and 74 MB.
- The inputs that showed the bug are now refused.

An inline `<svg>` over `INLINE_SYNC_WORK` converts on a task instead of
during the build, which now happens at roughly 40 short labels.
