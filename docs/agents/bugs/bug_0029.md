# bug_0029 — Links from a Fluent translation never match `:hover`/`:active`/`:focus`

| field | value |
|---|---|
| ID | bug_0029 |
| Status | **fixed** (uncommitted at filing) |
| Severity | medium (interaction styling silently dead for all markup that comes from a Fluent value — links, and any inline element's run-level properties) |
| Component | `build.rs` (collection state maps + `run_extras`) |
| Discovered by | user report (the `links` example: translated inline links don't highlight on hover; template links do) |
| Discovery agent | omp session, GLM 5.3 — diagnosis |
| Commit at discovery | uncommitted `links`/`inputs`/`forms` examples work |
| Date | 2026-10-10 |
| Regression coverage | `translated_links_hover_like_template_links` (`tests/signals.rs`): translated and template link spans hover and recolor (`color` + run-level `background-color`) |

## Symptoms

In the `links` example, hovering the two links that come from the
`links-intro` Fluent message (the `<a>` markup is inside the translation
value) does nothing; hovering the template's standalone links highlights
them. Clicking works in both cases (the bindings live on the link spans
either way).

## Root cause

The collection styles inline runs against an element-state map keyed by
DOM handle:

- the map was built from entities' `DomNode` handles — for link spans
  spawned from a translation, those handles index the *re-parsed
  translation fragment* (a separate `tl` parser), not the document;
- the fragment walk (`walk_translation`) built its `Ctx` with
  `states: None` ("fragment handles index the fragment, not the
  document"), so translated runs cascaded with `Pseudo::default()` —
  `a:hover`, `a:active`, `a:focus` never matched.

A second path had the same effect: `Styler::run_extras` (the run-level
`background-color`/`text-decoration`) cascaded with `Pseudo::default()`
unconditionally, so even template links couldn't state-style their
background.

## Fix

`build_html_ui` now collects the fragments' element states separately:
the walk tracks, per entity, which translated element's fragment its
`DomNode` handles belong to (an element whose DOM handle is in the
`LocalizedText` map starts a fragment; only document elements do —
fragments aren't localized again). `walk_translation` hands the fragment
walk its own map (`Ctx.fragments`), so `:hover`/`:active`/`:focus` match
inside translations. States from the last build: a translation that
changed misses and styles unhovered until the fresh build.

`run_extras` takes the element's state like `style_of` does, so
`a:hover { background-color }` applies to the span.

## Notes

- Keying per translated element keeps different fragments' handle spaces
  apart (fragment handles are plain indices; two fragments' handle 3 are
  different elements).
- Regression test hovers both link kinds by probing the block's line (link
  spans have no `Node`, so there is no rect to hit directly) and asserts
  the hover color and background on each span.
