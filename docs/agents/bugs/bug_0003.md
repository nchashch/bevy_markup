## Symptoms

Inserting `HtmlDebugOutline` rebuilt the UI as a DOM outline, but **removing
it did nothing**: the entity stayed in outline mode indefinitely. The stale
state persisted until some unrelated input changed and forced a rebuild.

## Discovery

The `proptest-stateful` state machine applies random operation sequences
(theme/locale/context/outline toggles) to one long-lived `HtmlUi` and
model-checks the dump after every op. A minimal failing sequence of
`[ToggleOutline, ToggleOutline]` hung in the harness's settle step — at first
misread as a false alarm, because the dump *looked* like outline-off content;
it was in fact the outline *text* (which embeds the raw text inside its
pre-formatted run). Once that was recognized, the world was demonstrably
stale: the build system had skipped the removal.

## Root cause

The dirty check only watched the component while present:

```rust
outline.as_ref().is_some_and(|outline| outline.is_changed())
```

After `remove::<HtmlDebugOutline>()` the query item yields `None`, so this
term is `false`; component *removal* produces no `Ref::is_changed` signal and
Bevy's `RemovedComponents` stream was not consulted. AGENTS.md's trigger list
only ever mentioned "outline marker **added**".

## Fix

```rust
mut removed_outlines: RemovedComponents<HtmlDebugOutline>,
...
let removed_outlines: HashSet<Entity> = removed_outlines.read().collect();
...
let dirty = ... || removed_outlines.contains(&entity) || ...;
```

## Regression coverage

`tests/stateful.rs` generates `ToggleOutline` ops; any sequence with a removal
(once the preconditions fix excluded same-value ops) exercises the removal
path every run. The reference model checks the outline markers and the styled
runs in their respective states.
