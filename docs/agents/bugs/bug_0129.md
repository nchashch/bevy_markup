| field | value |

## Symptoms
The test's dump shows the **unstyled** UI: `"Plain highlight and "` as one
run, the `<img>` attribute-sized (`32x24`), no background/line-through
styling — while `settle()` had already confirmed the stylesheet's
`is_loaded_with_dependencies`. The expected dump (the styled build) is
the one every isolated run produces.

## Minimal repro
`cargo test -j 4` (the whole suite, so all binaries link/run
concurrently) at `3b0187f`, ~1-in-3 runs; isolated runs don't reproduce
(8/8 clean). Captured output is quoted in the discovery session log
(2026-10-15, "the flake needs the full suite's load").

## Suspected mechanism (unconfirmed — needs investigation)
A build ran while the sheet was still loading (the unstyled path), and
the `AssetEvent::LoadedWithDependencies` that should have triggered the
restyle was missed — either consumed by a frame whose decision was
`Skip`, or a `Wait`-latch edge where the event and the asset's ready
state race across the frame boundary. The pending-change latch
(`RebuildState::pending`) is supposed to keep such a change alive; the
failure suggests an event window it doesn't cover. The new ADR 0027
scoping is *not* obviously involved (the failing path is a plain
stylesheet load → full restyle; the scoped-restyle code only widens the
reuse gate) — but the first appearance coincides with the ADR 0027
waves, so bisect before assuming pre-existing.

## Next steps
- Instrument `build_html_ui` under the failing load: log
  `(decision, own_phase, event_seen)` per frame for the inline test.
- If confirmed pre-existing, it's the settle-polling weakness (AGENTS.md
  Testing TODO 5) wearing a correctness costume: `TestUi::settle`'s
  asset check passes once the asset is loaded, but the *restyle build*
  may still be pending — settle should also demand that no
  `style_pending` UI remains.
