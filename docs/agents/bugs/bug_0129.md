## Symptoms
`cargo test -j 4` (the whole suite) failed
`inline_backgrounds_decorations_and_images` ~1-in-3 runs: the
broken-sheet step's dump showed the **previous styled build** (the
background/decoration/image-size styles still applied) instead of the
unstyled one. Isolated `--test html_ui` runs never failed (8/8 clean).

## Root cause
TWO bugs, found in sequence:

1. **The test** (the first fix): the broken-sheet step — a deliberately
   missing file — waited with `settle_quiet()` plus a fixed
   `update(10)`. The failed load resolves on bevy's io task pool, which
   the full suite's parallel pools starve past ten frames; the stale
   styled dump failed the assert. Fixed: `settle()` (the swap *does*
   rebuild once the load fails).

2. **The crate** (the real bug the test's fix exposed): the swap's
   `Restyle` latches during the sheet's `Wait`, but the resolution
   frame — the one where the load *fails* — has all its style flags
   consumed (`default_changed` was eaten by the Wait frame), so ADR
   0029's `full_style` read FALSE and the latched restyle ran **scoped**:
   nothing was flipped, nothing inherited changed, everything re-cascaded
   to *the same styled values*, and the unstyled dump never appeared.
   Fixed: `RebuildState::pending_full_style` — a full-page style signal
   latches its full-page-ness alongside the pending update (the same
   "the change survives the Wait" rule the pending latch already uses),
   the consumer ORs it into `full_style`, and
   `style_pending_applied` clears it. Unit-tested in `rebuild::tests`
   (`a_full_page_change_latched_in_a_wait_survives_to_the_resolution`).

## Fix
The test's wait (`settle()`) + the latch
(`a_full_page_change_latched_in_a_wait_survives_to_the_resolution`);
six consecutive full-suite runs green after both (was ~1-in-3).
