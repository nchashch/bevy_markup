# bug_0129 — `inline_backgrounds` raced the failed-sheet restyle under full-suite load

| field | value |

| ID | bug_0129 |
| Status | **fixed** (the test's fix; the crate was never at fault) |
| Severity | low (test flake only) |
| Component | `tests/html_ui.rs`'s `inline_backgrounds_decorations_and_images` (its broken-sheet step) |
| Discovered by | the ADR 0027 test waves: `cargo test -j 4` (the full suite) failed the test ~1-in-3 runs (2026-10-15); never in isolation |
| Discovery agent | omp session, `glm-5.3-flash` |

## Symptoms
`cargo test -j 4` (the whole suite) failed
`inline_backgrounds_decorations_and_images` ~1-in-3 runs: the
broken-sheet step's dump showed the **previous styled build** (the
background/decoration/image-size styles still applied) instead of the
unstyled one. Isolated `--test html_ui` runs never failed (8/8 clean).

## Root cause
The test's second phase swaps `DefaultStylesheet` to a **deliberately
missing file** (`plain.css`) — the failed-sheet case — and then waited
with `settle_quiet()` plus a fixed `update(10)`. The failed *load*
resolves on bevy's io task pool: under the full suite's parallel load
every binary's pools oversubscribe, the task starves past those 10
frames, the restyle (the `Failed` phase → `Source::Unstyled`) has not
run yet, and the stale styled dump fails the assert. The fixed frame
count was the bug; `settle()` (which waits for the rebuild the same way
every other test does) is correct — the swap *does* rebuild, once the
load fails, and settle's asset check already tolerates a failed asset
(`is_failed` passes).

The initial suspicion (a missed `LoadedWithDependencies` event / a
`Wait`-latch edge in the crate) was disproven by instrumentation: a
`Source::Unstyled` log in `build_html_ui` never fired in the failing
runs — the restyle hadn't been *decided* yet, not missed. The scoping
work (ADR 0029) is not involved.

## Fix
`tests/html_ui.rs`: the broken-sheet step waits with `settle()`. Six
consecutive full-suite runs green after the fix (was ~1-in-3).
