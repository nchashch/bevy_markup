# bug_0028 — The demo's panels never scroll: the layout grows to the tallest content instead

## Symptoms

`cargo run --example demo`: the mouse wheel over a framed panel, PageUp /
PageDown and the right stick on a focused panel never move its content. The
tallest panel (the l10n DOM outline) is cut off at the window's bottom edge.

## Diagnosis (measured)

A throwaway build printed `ComputedNode` sizes from the `HtmlUi` root down to
`#slot-inventory`. At 1× in a 2560×1245 window:

```
(root)          2560x1245
.columns        2560x1263   ← taller than the root
.column          493x1231
.panel.fill      493x1231
.viewport        437x1191   content 785
```

At `UiScale(2.0)` (a 1280×622 logical window): the root is 622 tall, but
`.columns` is 3068, and every viewport is 2996 tall — the l10n outline's
content height. All four viewports report `content ≤ size`: **nothing ever
overflows a viewport, so `ScrollArea` (wheel) and `scroll_focused` (keys,
stick) have zero range**; the overflow happens at the root, which clips it.

## Root cause

bevy_markup containers default to `flex-shrink: 0` (documented in
`src/style.rs`; browsers default to 1). The demo chrome used the browser
idiom `flex-grow: 1; min-height: 0; overflow-y: scroll`, but `min-height: 0`
only matters for an item that may shrink. `.columns`, `.panel.fill` and
`.viewport` kept their content-sized basis, so the tallest content set the
height of the whole chain. `.column` alone already opted in (`flex-shrink: 1;
flex-basis: 0`, with a comment about this very default).

## Fix

In the "Demo chrome" block of all four themes, `.columns`, `.fill` and
`.viewport` get `flex-shrink: 1; flex-basis: 0; min-height: 0`, with a
comment on the scroll chain. After the fix (same driver):

- 1×: root 1245, `.columns` 1245, viewports 1173; the l10n outline overflows
  (1191 > 1173) and scrolls.
- 2×: viewports 550 tall; inventory (max 984) and l10n outline (max 2445)
  overflow. Wheel down 3 lines → 300, 30 lines → 984 (clamped), up 10 → 0;
  wheel over the l10n outline scrolls only it (500); PageDown on the focused
  inventory → 440; right stick down 0.5 s → 891.

## Remaining

At 2× the middle column (about / language / theme panels, no viewport)
was still taller than the window and clipped. Follow-up in the same change:
it scrolls as a whole (`is="scroll-column"` → `ScrollArea`,
`.column.scrolling { overflow-y: scroll }`), and keyboard/gamepad focus moves
scroll the focused option into view (`shell::scroll_focus_into_view`, Bevy's
`ScrollIntoView`, gated on `InputFocusVisible` — ungated, startup `autofocus`
scrolled by a not-yet-settled layout to 1023 with a real maximum of 538).
Measured at 2×: wheel 0 → 300 → 0; ↓ through all seven options reveals each
at the bottom edge (220 … 518 of 538); ↑ back to visible options doesn't
scroll.

The `flex-shrink: 0` default makes the standard browser recipe for a
scrolling panel silently not work. Whether the default should change is a
library design question (it would alter every existing layout), not part of
this fix; documented in `AGENTS.md` "Limits and next steps".
