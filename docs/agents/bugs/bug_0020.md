# bug_0020 — `pointer-events: none` didn't stop clicks on a block's text

| field | value |
|---|---|
| ID | bug_0020 |
| Status | **fixed** (working tree, same commit cycle as discovery) |
| Severity | medium (any text-bearing element styled `pointer-events: none` stayed clickable and hoverable; invisible overlays could eat clicks) |
| Component | `src/build.rs` — `spawn_spec` / `apply_spec` text spans |
| Discovered by | new picking-driven end-to-end tests (`tests/signals.rs`, `pointer_events_none_silences_an_element`) |
| Discovery agent | model `zai/glm-5.3-flash:high` |
| Date | 2026-10-05 |
| Regression coverage | `pointer_events_none_silences_an_element` (`tests/signals.rs`) |

## Minimal reproduction

```css
#btn { pointer-events: none }
```
```html
<div id="wrap"><div id="btn" data-on-click="x"><p>Nope</p></div></div>
```

Click where the button is (real pointer input, real picking): the `x`
signal fired anyway, and the element counted as `:hover`-able. `Pickable::IGNORE`
was correctly on the container and the `p` text node — components verified
directly — yet the click still reached the button.

## Root cause

Bevy's UI picking backend reports the *text span entity* (a child of the
`Text` node) as the hit target for text, and bevy_picking's hover map looks
up `Pickable` on that target entity. The spans carried no `Pickable`, so
they were hoverable and blocked by default: the text-section hit won the
hover map, the event bubbled from the span to the block's observer, and the
`pointer-events: none` computed on the block and its text node never came
into play.

## Fix

`spawn_spec` and `apply_spec` keep the spans in step with their block's
computed `pointer-events`: `Pickable::IGNORE` on every span of an ignored
block, taken back (`remove::<Pickable>`) when a restyle re-enables it. The
hit then falls through to whatever is behind, as in a browser.

## Note

The `Pickable` lookup on the span entity rather than the hit entry's
recorded component is arguably a bevy_picking/bevy_ui interplay quirk (the
backend attaches the text node's `Pickable` to the hit, but the hover map
re-queries the target entity, which for text hits is the span). See
`docs/agents/bugs/UPSTREAM.md` for candidates worth reporting upstream.
