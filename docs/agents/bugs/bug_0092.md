## Symptoms and repro
Two unbounded recursions: `Substitution::substitute` recursed through
function arguments, fallbacks and chained `var()` with no shared counter
(`MAX_VAR_DEPTH` counted only `var()` links) — 64 links × 10 nested `f(`
(~3 KB) overflowed a 2 MiB thread and aborted; and lightningcss's parser
recurses per parenthesis, so ~500 nested `(` aborted at load.

## Root cause and fix
One depth counter (`MAX_SUBSTITUTE_DEPTH` = 256) now bounds all
substitution recursion; untrusted CSS text (sheet source, `style=`
attributes, substituted values) is pre-scanned by `nesting_over_limit`
before lightningcss parses it. G34: depth-cap failures are no longer
memoized, so results don't depend on reference order. The pre-scan
counted only `(` — nested *rules* still aborted (bug_0106).
