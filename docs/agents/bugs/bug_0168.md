# bug_0168 — One inserted or removed row materializes a windowed document for a frame

| field | value |
|---|---|
| ID | bug_0168 |
| Status | **open** |
| Severity | medium (performance: a 1000-row windowed list builds all 1000 rows the frame after one row is added or removed above its end; the next frame is back to the band) |
| Component | `src/build.rs` (`pair_trees_into`, `pair_node`: sibling alignment) |
| Discovered by | measured while fixing bug_0166 (`one_inserted_row_builds_only_the_band`) |
| Discovery agent | Claude Code session, `claude-opus-5-5` |

## Root cause
The skeleton aligns sibling lists by position only. At the root it zips
the old and fresh children, so after an insertion every later row pairs
with its neighbour: unclean, so `Ctx::cull` refuses to cull it
(bug_0161). A nested container whose child count changed isn't paired at
all, so its subtree's heights drop and its frame stops culling. Only a
removal at the root's end is free.

## Proposed fix
Align each sibling list by its common head and tail (pair from both ends
while the subtrees' source is equal, pair the middle by position), at the
root and in nested containers, and pair the container itself even when
its count changed. Shifted tail items under an `ol` must not count as
clean (their marker number changed). A design change to ADR 0021's
pairing; it needs an ADR and the freshness properties
(`content_update_matches_a_fresh_build`) plus the windowing property.
