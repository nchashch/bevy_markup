## Symptoms and repro
`<p data-l10n-id="hi" data-l10n-args='{{ {"who": who} }}'>FALLBACK</p>`
with `who = "Ada 👨‍👩‍👧"` (zero-width joiners) or `"Jose\u{301}"` (a
combining accent) or any control character showed `FALLBACK`: the
translation failed silently. Plain names, `'`, tabs and `{% raw %}` were
fine.

## Root cause and fix
Tera prints a map's strings with Rust's `Debug` formatting
(`tera::Value`'s `Display`, `write!(f, "{:?}", ..)`), which escapes
non-printable and grapheme-extending characters as `\u{200d}` and NUL as
`\0` — not JSON. The attribute's JSON parse failed, the args were an error,
and localization fell back. The map-literal pattern (bug_0119) and the
older whole-map `'{{ args }}'` pattern both print this way. Fix:
`template::parse_attribute_json` rewrites those two escapes into JSON's
`\uXXXX` (surrogate pairs above U+FFFF; an escaped backslash before
`u{` stays text) before parsing, at all three attribute parsers.
