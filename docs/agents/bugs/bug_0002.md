## Symptoms

Loading a stylesheet whose selector contains a multi-byte UTF-8 character
 panicked:

```
thread '…' panicked at src/cascade.rs:145:
start byte index 1 is not a char boundary; it is inside '�' (bytes 0..3 of string)
```

Since stylesheets are app data, any unlucky/malicious CSS file (e.g. a
non-ASCII type selector like `é {}`, or `.é {}` after a dot) crashed the app
at asset load.

## Discovery

Found immediately by the first `cargo fuzz run css` campaign
(`-max_total_time=15`): libFuzzer reported `deadly signal` from the Rust
panic. The crash input was minimized by hand from the fuzzer's artifact.

## Root cause

`Compound::parse` advanced through the selector by character but sliced by
byte:

```rust
while let Some(kind) = rest.chars().next() {
    let body = &rest[1..];   // one BYTE, not one char
```

For a multi-byte `kind` (anything not `.`/`#`, e.g. `é` in `é {}`), byte
index `1` lands inside the character → `slice_error_fail` panic.

## Fix

Check the kind *before* slicing and advance by `kind.len_utf8()`:

```rust
while let Some((_, kind)) = rest.char_indices().next() {
    if kind != '.' && kind != '#' {
        return None; // unsupported: combinators, pseudos, non-ASCII idents
    }
    let body = &rest[kind.len_utf8()..];
    ...
}
```

p23's ident rules are ASCII-only by design, so a non-ASCII selector character
now simply marks the rule unsupported (skipped at `debug`), consistent with
every other unsupported-selector path.

## Regression coverage

`src/cascade.rs::tests::multibyte_selector_characters_are_skipped` —
`é {}`, `.é {}`, `p.é {}` are skipped while `p {}` still applies.
