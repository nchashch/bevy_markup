## Symptoms

In an app with one `Camera3d` and no `IsDefaultUiCamera`, every
`HtmlWorldAnchor` root stayed `Visibility::Hidden` with
`HtmlWorldAnchorView { distance: 0.0, on_screen: false }`, and `left`/`top`
were never set. prototype_19 didn't show it: its client marks a camera
`IsDefaultUiCamera` explicitly, as does the test harness's layout camera.

## Root cause

With no anchor camera and no `UiTargetCamera`, `place_world_anchored` looked
for a camera with `Query<Entity, With<IsDefaultUiCamera>>` only. Bevy UI's
own default is wider: `DefaultUiCamera::get()` returns the marked camera,
else the highest-order camera rendering to the primary window.

## Fix

Use `DefaultUiCamera` (`default_camera.get()`). The type docs now say
"the `IsDefaultUiCamera` one, else the window camera Bevy UI renders with".

## Reproduction / regression test

`world_anchor_uses_the_implicit_default_ui_camera`: removes the harness's
marker, points its camera at a primary window, anchors to the origin and
asserts the anchor is on screen and visible. It fails before the fix
("projected with the window's camera").
