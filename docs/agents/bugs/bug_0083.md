## Symptoms
A reused subtree whose parent held an app-nested `HtmlUi` root made the refresh's entity-count check disagree, and the whole subtree's `DomNode` handles stayed in the previous document. In the shapes probed the reuse-skip arm never engaged with a nested root present, so no end-to-end falsification was found; the fix is strictly more correct and the slot pattern (persist + hover across an insertion) is pinned by a test.

## Repro
A reused subtree whose parent holds an app-nested `HtmlUi` root after
an insertion — the count disagreed and the refresh gave up.

## Root cause and fix

The refresh's entity-count check compared ALL children against the
spec's children; nested roots sat among them. `700d047` filters nested
roots out before zipping. No end-to-end falsifying case was found (the
reuse-skip arm never engaged with a nested root present in the shapes
probed) — the fix is structural, and the slot pattern is pinned by
`signals::hover_survives_a_rebuild_around_a_nested_ui_root`.
