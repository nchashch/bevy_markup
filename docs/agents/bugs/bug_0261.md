## Symptoms

With the stylesheet:

```css
#box {
  padding: calc(-10px);
  border-width: calc(-5px);
  gap: calc(-8px);
  width: calc(-20px);
  border-radius: calc(-6px);
}
```

the resulting Bevy `Node` receives `padding = Px(-10.0)`, `border = Px(-5.0)`, `row_gap = Px(-8.0)`, `width = Px(-20.0)`, and corner radius `Px(-6.0)` on both axes (all negative and unclamped), whereas plain `padding: -10px` is rejected.

## Root cause

`non_negative_lp` (`src/css/property.rs:538–545`) rejects negative `Lp::Dim` and `Lp::Percent` literals, but unconditionally accepts every `Lp::Calc(_)`. Accepting `calc(-10px)` at parse time matches CSS Values 4, but the spec requires clamping negative `calc()` results to `0` at computed/used-value time for non-negative properties (`padding`, `border-width`, `gap`, `width`/`height`, `min-*`/`max-*`, `border-radius`, `font-size`). Neither `non_negative_lp` (for folded `CalcExpr::Val`) nor `resolve_calc` (`src/build.rs:4349–4353`, for runtime-resolved expressions) clamps the value to `>= 0.0`.

## Fix

Clamped folded `Lp::Calc(Some(CalcExpr::Val(val)))` to `>= 0.0` via `non_negative_val` in `non_negative_lp` (`src/css/property.rs`), added `CalcProp::non_negative()` (`src/cascade.rs`) for `width`/`height`/`min-*`/`max-*`/`flex-basis`, and clamped layout-resolved values to `value.max(0.0)` in `build::resolve_calc` (`src/build.rs`) while keeping signed properties (`margin`, insets) negative. Unit, property, and layout-integration tests all failed before the fix and pass with it.
