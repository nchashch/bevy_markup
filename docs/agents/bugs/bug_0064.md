## Symptoms

While the active locale bundle was loading or had failed, `localize`
returned early and kept the old `LocalizedText` map; the build then
applied those stale handles to a freshly rendered document without
re-checking `data-l10n-id` — arguments frozen, translations misplaced
across structural changes.

## Root cause

The early return kept the stale per-element map, and the build's
localize walk trusted the existing map for elements it didn't re-resolve.

## Fix

While the bundle is absent, a changed render drops the stale map — the
elements show their fallback content until the bundle arrives, then
localize normally (`402362c`).
