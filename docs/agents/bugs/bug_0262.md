## Symptoms

In `TestUi::with_pointer`, with a visible `HtmlUi` containing `<button id="vis_btn" data-on-click="vis">` and an `HtmlModal` `HtmlUi` containing `<button id="hidden_btn" data-on-click="hidden" autofocus>` spawned as a child of an app entity carrying `Node { display: Display::None, .. }`:

- `InputFocus` moves to `hidden_btn`.
- `HtmlFocus::tab_order()` returns only `[Some("hidden_btn")]`, locking `#vis_btn` out of navigation.
- `HtmlFocus::activate(ActivationInput::Synthetic)` emits `["hidden"]`.

## Root cause

[bug_0242](bug_0242.md) (`review_0009` M04) fixed `display: none` inside an `HtmlUi` tree, but stopped at the `HtmlUi` root boundary:

- `displayed_none` (`src/focus.rs:534–552`) breaks out of the ancestor loop at `if roots.contains(ancestor) { break; }` (`:547–549`), ignoring `Display::None` on any app-owned ancestor above the `HtmlUi` root.
- `active_modal` (`src/focus.rs:402–419`) walks the full `ChildOf` chain for `visible_in_hierarchy`, but checks `node.display != Display::None` only on the modal root entity itself (`:410–412`).

## Fix

Removed the `if roots.contains(ancestor) { break; }` stop in `displayed_none` so it walks the full `ChildOf` chain (matching `visible_in_hierarchy`), and updated `active_modal` to check `!displayed_none(entity, nodes, parents)` instead of only the modal root's own `Node`. The regression test (covering initial hide, show, and re-hide transitions) failed before the fix and passes with it.
