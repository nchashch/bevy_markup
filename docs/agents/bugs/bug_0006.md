## Symptoms

A `data-l10n-id` on anything but a block (`h1`–`h6`, `p`, `li`, `pre`) had no
effect: `<div data-l10n-id="box"><p>Child paragraph</p></div>` kept showing
"Child paragraph", and `<p>Inline <span data-l10n-id="inline">fallback</span>
element</p>` kept "fallback", although the message existed and the Localize
stage had resolved it. Nothing was logged. fluent-dom translates any element.

## Discovery

The first run of the Fluent oracle: `scripts/fluent_oracle.sh` recorded what
`@fluent/dom` 0.10.2 (in jsdom 30.1.1) makes of the vector, and the test
diffed p23's localized build against p23's build of that reference:

```
    div
+     p
+       "Child paragraph" serif 20px #00ff00
-     -
-       "Container text" serif 20px #00ff00
    p
+     "Inline fallback element" serif 20px #ffffff
-     "Inline translated element" serif 20px #ffffff
```

## Minimal reproduction

```html
<div data-l10n-id="box"><p>Child paragraph</p></div>
<p>Inline <span data-l10n-id="inline">fallback</span> element</p>
```

```ftl
box = Container text
inline = translated
```

## Root cause

`l10n.rs` (`resolve_all`) resolved `data-l10n-id` on every element, but
`build.rs` consulted `LocalizedText` only in `collect_node`'s block branch.
Containers and walked-through elements recursed into their own children, and
`push_runs` (inline elements inside a block) always used the element's
children.

## Fix

One helper, `walk_translation`, parses an element's translation as a
fragment and walks it in place of the children. Blocks
(`push_content_runs`), containers and walked-through elements
(`collect_node`) and inline elements (`push_runs` → `push_content_runs`) all
go through it; a missing or failed message still falls back to the own
content. Fragment contexts carry an empty translation map, because fragment
node handles index the fragment, not the source document.

## Notes

- Same shape as bug_0003: the upstream stage produced the data, the build
  stage never looked at it.
- Mixed inline content in a translated container (`Mixed <b>bold</b> text`)
  becomes one anonymous block per text piece. That predates this bug and
  happens identically for untranslated HTML (see AGENTS.md limits).
