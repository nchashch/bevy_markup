# bug_0024 — Right and middle clicks fired `data-on-click`

| field | value |
|---|---|
| ID | bug_0024 |
| Status | **fixed** (uncommitted at filing) |
| Severity | medium (a right or middle click activated any button: a context-menu gesture could confirm a dialog or start a game) |
| Component | `src/signals.rs` — the pointer observers |
| Discovered by | code reading while designing signal sources (`ElementSignal::source`) |
| Discovery agent | omp session, Claude Opus 5.5 (Anthropic) |
| Date | 2026-10-05 |
| Regression coverage | `other_buttons_auxclick_instead_of_click` (`tests/signals.rs`) |

## Minimal reproduction

```html
<div id="btn" data-on-click="buy"><p>Buy</p></div>
```

Right-click (or middle-click) the element: a `buy` `Click` signal fired, the
same as a left click.

## Root cause

The `Pointer<Click>` observer emitted the element's `click` bindings for
every `PointerButton`; nothing looked at `Click::button`. Browsers fire
`click` for the primary button only (`auxclick` for the others).

## Fix

`Click` events map to `SignalTrigger::Click` for `PointerButton::Primary` and
to the new `SignalTrigger::AuxClick` (`data-on-auxclick`) otherwise. Every
pointer signal now carries `SignalSource::Pointer { pointer, button,
position, count }`, so handlers can tell the buttons and pointers apart;
`press`/`release` still fire for every button, as in browsers.
