## Root cause and fix
Bevy clamps the scroll offset only for its layout
(`ComputedNode::scroll_position`) and keeps the app's `ScrollPosition`.
The band was placed by `ScrollPosition`, so an offset past the end put
the band below the content: everything culled, while the view showed
the last rows. Fix: `visible_scroll` clamps the offset to the last
layout's scroll range (taffy's `scroll_height` from `ComputedNode`); the
rebuild trigger and the band both use it. The mutation run's strict
root-box test (`the_root_box_and_scale_bound_the_band_exactly`) caught a
first version adding the *vertical* scrollbar's width: taffy's range adds
the horizontal scrollbar's height.
