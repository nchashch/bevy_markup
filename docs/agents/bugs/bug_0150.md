## Symptoms and repro
`<section><p>{{ a }}</p><p>{{ b }}</p><p>{{ c }}</p><p>{{ d }}</p></section>`,
change `d`: nothing reused, the skeleton struck (`(false, 1)`). The same
paragraphs at the document's top level reused three of four. The
benchmarks didn't see it: their rows sit at the top level.

Measured (divan, release, 100 samples, median; `changing` = the
benchmark page, `changing-nested` = the same inside `<main>`):

| workload | 120 rows | 600 rows |
|---|---|---|
| `changing` (top level) | 0.43 ms | 1.42 ms |
| `changing-nested`, before | 0.95 ms | 3.61 ms |
| `changing-nested`, fixed | 0.66 ms | 2.21 ms |

## Root cause and fix
`pair_node` entered a node in `pairing`/`reverse` only when its whole
subtree was clean. ADR 0029's gate then decides a re-collected element's
children by comparing its fresh style with its cached spec's
(`children_inherited_changed`), found through `pairing`: a changed
container had no entry, so the comparison read "changed" and every child
re-collected. Before ADR 0029 there was no such gate, so nested clean
subtrees reused. Fix: every tag pair that matches (tag, attributes, child
count) is paired whether or not its subtree is clean; `clean` alone gates
reuse. A side benefit: a changed container's entity now maps to the fresh
document for its interaction state (`reverse`).
