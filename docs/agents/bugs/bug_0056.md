## Symptoms

`lead = { $n } items here` rendered `\u{2}0\u{3} items here` — the
argument was lost and the substitution markers reached the UI.
`A { $x } B { $y }` lost `$y`; multi-line paragraphs (the normal Markdown
shape) lost *every* argument.

## Root cause

The cache stored one literal part per line and none for a missing
leading/trailing text, so `parts[k]` didn't correspond to marker `k`;
back-to-front substitution then wrote values into the wrong gaps.

## Fix

The cache aligns its `n + 1` literal runs with the `n` markers for every
pattern shape (empty parts at the edges when the pattern starts or ends
with a placeable, multi-line runs joined); the first part anchors the
text's start and the last its end, and each gap replaces its marker
verbatim. A text that no longer splits returns `None` and the caller
falls back to the per-value conversion (`402362c`).
