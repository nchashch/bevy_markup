## Symptoms

After content changes, `:hover`/`:active` inside a reused subtree stops
applying (the element stays unhovered), and a stale handle can collide
with another element's and hover the wrong one.

## Root cause

The reuse skip wrote the *root's* `DomNode` handle only; descendants kept
the handles they were spawned with. The state walk maps the *current*
document's handles, so those entities were no longer reachable under
their old handles.

## Fix

`refresh_cached_handles` walks the reused subtree and rewrites every
`DomNode` positionally from the remapped spec tree (the entities were
spawned from that tree and their content is unchanged); a mismatching
child count bails to the next full visit (`0ede9b6`). App-nested `HtmlUi`
roots keep their own state.
