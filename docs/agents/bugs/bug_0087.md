## Symptoms

An app that sets `AssetPlugin::unapproved_path_mode = Allow` still cannot
`{% include %}` or name `.ftl` resources outside the asset root: the
loaders enforce Forbid themselves (`read_asset_bytes` skips Bevy's check,
so the loaders added their own — bug_0069).

## Root cause

`LoadContext` exposes no read of the mode (the field is private, and
`AssetServer` has no accessor), so the loaders cannot honor it. A
crate-level config resource would be new public API for a discouraged
setting.

## Fix

Documented on both check sites (`e807576`). Re-check on any bevy_asset
bump: if the mode becomes readable, consult it.
