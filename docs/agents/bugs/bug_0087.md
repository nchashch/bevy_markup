## Symptoms

An app that sets `AssetPlugin::unapproved_path_mode = Allow` still cannot
`{% include %}` or name `.ftl` resources outside the asset root: the
loaders enforce Forbid themselves (`read_asset_bytes` skips Bevy's check,
so the loaders added their own — bug_0069).

## Root cause

CORRECTION (review_0003): the original claim — "`LoadContext` exposes
no read of the mode, so the loaders cannot honor it" — is false. The
mode IS readable: `app.get_added_plugins::<AssetPlugin>()[0]
.unapproved_path_mode` in `BevyMarkupPlugin::build`, and the crate
registers its own loaders, which could carry the mode. Honoring it
remains undone deliberately (a discouraged setting; not worth the
plumbing yet) — but it is a choice, not an API gap.

## Fix

Documented on both check sites (`e807576`). Re-check on any bevy_asset
bump, or honor the mode via the plugin-registered loaders.
