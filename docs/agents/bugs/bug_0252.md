# bug_0252 — `var()` substitution work wasn't bounded by its budget, and repeated per element

| Commit at discovery | `102de67` |
| Date | 2026-11-26 |

## Symptoms

Locally, release, the 31 inputs took 3–39 s each (median 4.6 s, up to
740 MB) in the `css` target. The slowest, 7.7 KB: a selector list of about
a thousand `*`, and one unclosed `var(` whose fallback runs to the end
of the sheet, through many brackets.

## Root cause

Two things multiplied each other:

1. `Substitution`'s 64 KiB budget counted only what it *wrote*. A
   fallback is read twice (cut out of its `var()`, then substituted) at
   every level of nesting (up to `MAX_SUBSTITUTE_DEPTH`, 256), and
   comments, whitespace and failed branches wrote nothing, so the reading
   was quadratic and free.
2. The cascade substituted every `var()` declaration again for every
   element and pseudo-state that missed the style cache, though the result
   depends only on the declaration, the sheet's custom properties and the
   context.

## Fix

The budget is charged for what each token reads (a block's opening, a
`var()`'s whole argument text) as well as for what is written. And
`HtmlStyles` keeps each `var()` declaration's parsed result (`Option<Decl>`)
by property and raw value, so it is substituted, nesting-checked and parsed
once per cascade. All 31 inputs now take 11–129 ms.
