## Symptoms

`separate_statements` put *every* `{% … %}` on its own line:
`src="{% if hd %}hd{% endif %}.png"` became
`src="\n\nhd\n\n.png"` (broken image, and a statement inside `id=`/`class=`
broke `by_id`/signal matching); a statement in a list item, heading or
table cell split the element. A later `{%` was preferred over an earlier
`{#` (`find("{%").or_else(find("{#"))`), changing list-vs-paragraph
behavior. A multi-line `{# … #}` comment failed the per-line purity check
and left an empty `<p class="markdown">` (visible at the top of the
committed `examples/assets/markdown/reader.md`).

## Root cause

The statement separator was a global "each tag gets its own line" rule
with no notion of the tag's context.

## Fix

Only statements that own their line are separated; inline statements
(attribute values, list items, headings, table cells) stay inline; the
earliest of `{%`/`{#` wins; statements inside fenced code, code spans and
multi-line comments are left alone (`402362c`).
