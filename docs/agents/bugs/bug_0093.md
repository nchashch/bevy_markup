## Symptoms and repro
`resolve_references` decides which `{% include %}`s are dependencies; a
Markdown template's code shows Tera literally, so includes there must not
count. Shapes it got wrong: a `~~~` fence after prose, indented code and
`{%raw-%}` (commented-out files loaded → NotFound); code spans across a
blank line and raw text holding a quote (real includes dropped →
"Unknown template").

## Root cause and fix
A hand-written approximation of CommonMark's block structure. `2e14ba8`
patched the five shapes (with a scan cursor kept linear for G14), but its
"indented code" rule was not CommonMark (lazy continuations, list
paragraphs, tabs) and escaped backticks still opened a span — review_0004
H04. bug_0108 replaces the approximation with pulldown's own code ranges.
