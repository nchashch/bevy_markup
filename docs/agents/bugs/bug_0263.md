## Symptoms

In a `.md` template, a 4-space indented body inside `{% macro %}`, `{% call %}`, `{% with %}`, or `{% autoescape %}` is parsed by `pulldown-cmark` as a CommonMark indented code block instead of Markdown, suppressing both formatting and template interpolation:

```jinja
{% macro card(title) %}
    **{{ title }}**
{% endmacro %}
{% call box() %}
    Some **bold** text
{% endcall %}
```

renders as:

```html
<pre class="markdown"><code>**{{ title }}**
</code></pre>
<div>
<pre class="markdown"><code>Some **bold** text
</code></pre>
</div>
```

Indented `{% with %}` bodies similarly render as `<pre class="markdown"><code>…</code></pre>`, while an indented `{% if %}` body renders as a paragraph with `<strong>`.

## Root cause

`block_tag` (`src/md.rs:210–228`) still matches Tera's removed `"component"` and `"set_global"` keywords, but omits MiniJinja's `"macro"`, `"call"`, `"with"`, and `"autoescape"` tags (and their `end*` closers). Because `separate_statements` inserts blank lines around own-line `{% ... %}` statements, bodies of unrecognized block tags are never dedented before CommonMark parsing.

## Fix

Added `"macro"`, `"call"`, `"with"`, and `"autoescape"` (and their `end*` closers) to `block_tag` in `src/md.rs` and removed Tera-only `"component"` and `"set_global"`. Both unit and property tests failed before the fix and pass with it.
