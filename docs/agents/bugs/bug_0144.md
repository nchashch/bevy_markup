## Symptoms and repro
`p:nth-child(-n+3) { … }` styled nothing; so did `p:nth-of-type(3n+1)`
and `p[data-x="a b"]`. (`2n+1` worked: lightningcss serializes it as
`odd`.)

## Root cause and fix
`Selector::parse` split compounds at the first whitespace, `>`, `+` or `~`
anywhere — inside `(…)`, `[…]` and quotes too — and the broken compound
failed the rule. Fix: `compound_end` scans for combinator characters at
depth 0 outside quotes (escapes skipped).

Two more in the attribute parse, found by the mutation run over this fix
(the quote arms survived): `Compound::parse` ended the selector at the
first `]` (`[data-x="a] b"]` broke), and the value kept lightningcss's
escapes — `[data-x='a"b']` serializes as `[data-x="a\"b"]`, so the
value `a\"b` never matched the dataset's `a"b`. Fix: `attribute_end`
finds the `]` outside quotes, and `css_unescape` resolves `\x` and hex
escapes.
