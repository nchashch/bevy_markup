## Symptoms

In a headless Bevy app with `BevyMarkupPlugin`, `.insert_resource(HtmlTemplateLimits { fuel: 100 })`, and a `Startup` system (or pre-frame-0 load) loading `{% for i in range(500) %}x{% endfor %}`:

- Loading before the first frame (including in `Startup`) settles as **`RenderedHtml::Ready`** (500 bytes rendered) instead of failing out of fuel.
- The identical load triggered after one frame fails with `RenderedHtml::Failed("engine ran out of fuel")`.

Both lowered security budgets and raised budgets for large legitimate templates fail to take effect on startup loads.

## Root cause

`BevyMarkupPlugin::build` (`src/lib.rs:350–362`) initializes `TemplateFuel::default()` (`1 << 22`) and schedules `sync_template_fuel` only in `PreUpdate`. In Bevy's `MainScheduleOrder`, `Startup` runs **before** `PreUpdate` on frame 0, so asset loads queued during `Startup` read the default `1 << 22` from `TemplateFuel`'s atomic before `sync_template_fuel` has ever run.

## Fix

`BevyMarkupPlugin::build` initializes `HtmlTemplateLimits` before `TemplateFuel` and seeds `TemplateFuel` from it (covering apps that insert `HtmlTemplateLimits` before the plugin), schedules `sync_template_fuel` in `PreStartup` as well as `PreUpdate`, and `BevyMarkupPlugin::finish` calls `template::sync_template_fuel_now(app.world())` (covering apps that insert `HtmlTemplateLimits` after adding the plugin). The integration test failed before the fix and passes with it for both insertion orders.
