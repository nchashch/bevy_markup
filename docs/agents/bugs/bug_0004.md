## Symptoms

Swapping the theme to a broken stylesheet, back to a good one, then to the
*same broken one again* left the UI showing the stale (good) theme forever.
Frame-by-frame instrumentation showed the build system running but skipping
the entity — the stylesheet resource's change signal had been consumed by a
frame in which the failed asset read as `Loading`, and by the time it read as
`Failed` again, the latch said "already handled".

## Discovery

The stateful machine's shrinker produced the minimal failing sequence

```
[SetTheme(Broken), SetTheme(Plain), SetTheme(Broken)]
```

with the harness panicking `UI never settled` on the third op. A
deterministic replay of that sequence (throwaway instrumented test, printing
`Builds` per frame) reproduced it exactly: builds stalled at `3 -> 3` across
the final op while the root line stayed on the Plain theme.

## Root cause

Two mechanisms interleaved:

1. **Re-requesting a failed asset** (`AssetServer::load` on a path that
   failed) flips its load state to `Loading` for a frame. In that frame the
   stylesheet gate takes the `Sheet::Loading → continue` path *before* the
   dirty check, so the `DefaultStylesheet::is_changed` signal from the swap
   is consumed without a build.
2. When the asset then fails again, `newly_failed` consulted a **global**
   `HashSet<AssetId>` latch populated during the *first* visit to the broken
   sheet — present, so no rebuild was scheduled. A user re-selecting a
   broken sheet is a new action and must rebuild.

## Fix

The latch became per-entity and self-clearing:

- `FailedSheets(HashSet<(Entity, AssetId<Stylesheet>)>)`.
- `newly_failed` = entity's current handle is failed **and** `(entity, id)`
  not latched.
- Styling with a ready sheet clears that entity's entries; a reload of the
  asset clears every entry for it (`LoadedWithDependencies`/`Modified`).

So each (entity, failure) rebuilds unstyled exactly once, and revisiting a
broken theme always fails fresh.

## Regression coverage

`tests/stateful.rs` theme ops include `Theme::Broken`; sequences that revisit
`Broken` after a good theme are generated routinely (the original minimal
case is found within a few seconds of search).

- Same family as bug_0001 and bug_0003: unobserved state transitions in the
