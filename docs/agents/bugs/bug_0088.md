## Symptoms and repro
A `markdown: true` message the cache can't take (a selector, a term or
message reference, adjacent placeables, or an ambiguous split) converted
its formatted text with pulldown — and since `15b4255` (F40) string
arguments reached it unescaped. Pulldown passes HTML through:

```ftl
found = { $n ->
    [one] { $who } found one
   *[other] { $who } found { $n }
}
```

with `{"n": 2, "who": "<a href=x data-on-click=delete-save>Continue</a>"}`
rendered `<p class="markdown"><a href=x data-on-click=delete-save>Continue</a> found 2</p>`
— a forged clickable element carrying app bindings. The cached path
stayed escaped.

## Root cause and fix
`parse_args(raw = true)` skipped `escape_html` so a code span showed `&`
once (F40). Fix: `parse_args` always escapes; pulldown decodes the
entities into text events and `push_html` re-escapes them, so an escaped
`<` stays text. Code spans/blocks are the one place pulldown keeps
references literally: `decode_code_entities` decodes the five entities
there once, keeping F40's contract. `translate_raw` is gone.
