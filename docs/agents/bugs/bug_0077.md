## Symptoms

An element at the top edge with `data-tooltip-placement="above"`: the
overlay's computed bottom was `view_h + gap` — the whole tooltip off
screen. `Right`/`Below` clamped; `Above`/`Left` didn't.

## Root cause

The `Above`/`Left` branches used a clamp form keyed on the overlay's
*extent* (only matched when known), so without a size they fell through
unclamped — and the extent-keyed form didn't clamp the inset alone.

## Fix

The far-edge form clamps the inset against the viewport limit
(`inset <= limit`) once the overlay's size is known, independent of the
extent match (`cd21ffd`, `97e16bc`).
