## Symptoms

`<p>{{a}}</p><p>{{b}}</p><p>{{c}}</p>`: after one change that marks every
element dirty (so the adaptive gate skips the reuse walk), then single
element changes, the UI shows `b = <old value>` where a fresh build shows
the new value — the skeleton went stale during the skipped build and the
retry served cached specs.

## Root cause

The gate-skipped build left the skeleton stale; the retry then paired
fresh content against cached specs whose entities had already been
updated from newer content. The skip guard (`DomNode` handle == paired
handle) checks *position*, not provenance, so the write was skipped.

## Fix

A build that runs without the reuse walk invalidates the skeleton's
spec/document pairing state (the skeleton is refreshed from the fresh
collect), so the next reuse pairs against current content (`0ede9b6`).
