## Symptoms and repro
`cargo fuzz build` (and every other fuzz driver, and `cargo test --features fuzzing`) failed to compile the lib:
`src/fuzz.rs` built `crate::cascade::Ancestor` with the old `element: HtmlElement { .. }, pseudo` field layout, but `Ancestor` had been reworked (review_0003 G05: drop the dataset, carry `tag`/`id`/`classes` directly, plus a new `submit` field for the form work) — three `E0560` errors. Plain `cargo test`/`check` don't see the module (it's `#[cfg(feature = "fuzzing")]`), so CI's non-fuzzing steps stayed green.

## Root cause and fix
The `Ancestor` rework didn't update `src/fuzz.rs` — exactly the failure mode the AGENTS.md gotcha ("API changes that touch `src/fuzz.rs`'s imports need `cargo check --lib --features fuzzing`") warns about. Fix: build the three harness chains with the new field layout (`tag`/`id`/`classes`/`submit` directly, no `element:` wrapper; `submit: false` — the fuzz pages carry no forms).

## Follow-up
`cargo check --lib --features fuzzing` should run in CI's main job (it currently only builds fuzz drivers nightly) so this class of break is caught on push.
