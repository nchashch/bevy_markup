# bug_0057 — String arguments were escaped twice through the Markdown cache

| field | value |
|---|---|
| ID | bug_0057 |
| Status | **fixed** (`402362c`) |
| Severity | high (any string argument containing `'`, `"` or `&` displayed HTML entities through `markdown: true` bundles) |
| Component | `src/l10n.rs` (`substitute`) |
| Discovered by | code review 2026-10-13 (finding R33, probe) |
| Discovery agent | omp session, `anthropic/claude-opus-5-5:high` |
| Commit at discovery | `b224619` |
| Date | 2026-10-13 |
| Regression coverage | `string_args_escape_once_through_the_cache` (`src/l10n.rs`), plus `string_args_survive_as_escaped_text` (proptest) |

## Symptoms

`O'Brien & Co` as a string argument displayed as `O&#39;Brien &amp; Co`
through the `markdown: true` cache path (the per-value path was correct).

## Root cause

`parse_args` already HTML-escapes string arguments (the build decodes
once, `build.rs`), and `substitute` escaped the formatted values again
before writing them into the cached HTML.

## Fix

The cache substitutes the (already escaped) formatted values verbatim —
escaped once (`402362c`).
