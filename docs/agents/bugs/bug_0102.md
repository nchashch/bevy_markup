## Symptoms and repro
Each child task received a `Vec<Ancestor>` copy whose ancestors carried a full `HtmlElement` clone (dataset included) — a 1 (G05) container × 100-deep ancestor chain blew memory. Separately, `run_walk`'s inline-nesting scan took no depth (F05 residual): a `<p>` with 20 000 nested `<b>` cost ~4×10⁸ ancestor clones/hashes per build, re-run on every hover restyle; AGENTS.md and a test comment claimed deep content was dropped by MAX_DOM_DEPTH, but the depth cap only applies to the main document walk, not run_walk's inline scan. Fixed: a shared `Rc<Vec<Ancestor>>` per level (O(1) clone) and a depth cap on run_walk (stops extending the chain, keeps the text, like the main walk).
