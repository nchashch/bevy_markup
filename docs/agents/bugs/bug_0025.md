## Observed

`cargo test --test stateful` fails about 1 run in 10 with

```
assertion `left == right` failed: signals mismatch (model UiModel { theme: Plain,
own: Some(Framed), locale: Raw, n: 0, outline: false, fonts_swapped: false,
pointer: Some(Vec2(76.0, 60.0)), entered: false, pressed: None, pending: [] })
```

The model predicted no signals (`pending: []`) for the op; the app emitted at
least one. Frequency at commit `9d84990` (worktree, nothing uncommitted): 1 of
12 runs; with the uncommitted cheaper-updates change: 2 of 12. So it predates
that change. It also failed once on 2026-10-05, during the custom-elements
work, under full-suite parallel load.

## Not yet known

The shrunk op sequence: proptest reports the minimal case only when a failure
reproduces during shrinking, and the runs that failed didn't print one. Next
step: run with `PROPTEST_CASES` raised and a fixed seed until it fails,
capture the persisted regression (`tests/stateful.proptest-regressions`), and
compare the emitted signals to the model's prediction for the last op. The
model's own state (`entered: false` with the pointer inside the button's
rect, `pressed: None`) suggests a theme/own-sheet op that moved the button
under a stationary pointer: the app may emit an `enter` the model doesn't
predict when the button's rect changes between settle frames.
