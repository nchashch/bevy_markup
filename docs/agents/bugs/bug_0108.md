## Symptoms and repro
`found = { $n -> [one] { $who } found one *[other] { $who } found { $n } }`
with `{"n": 2, "who": "[Continue](https://evil.example) ![x](../../save.png)"}`
→ `<a class="markdown" href="https://evil.example">Continue</a> <img
class="markdown" src="../../save.png" …>`. The cacheable `hi = Hello
{ $who }!` showed the same value as literal text — the result depended
on the message's shape.

## Root cause and fix
bug_0088's fix escaped HTML only; the per-value path converts the
formatted text with pulldown, so a value's `[`, `]`, `(`, `)`, `!`, `*`,
line breaks… were Markdown. Fix: on that path (`markdown_per_value`)
every Markdown-significant character of a string argument (ASCII
punctuation except `& < > " '`, which `escape_html` owns, plus `\n \r
\t`) rides through the conversion as a Private Use Area stand-in
(U+F700 + byte), restored afterwards — only stand-ins of those
characters, so a value carrying the stand-in of `<` can't forge markup. A
value shaped like a Fluent identifier (`two-handed`) is left as is so a
select still matches its variant key; such a value can't open a link,
image, list or heading.
