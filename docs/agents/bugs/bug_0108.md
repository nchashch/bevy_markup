## Symptoms and repro
`resolve_references` vs pulldown (`page.md`):

| shape | scanner | CommonMark |
|---|---|---|
| `Intro\n    {% include "real.md" %}` (lazy continuation) | protected | paragraph — include dropped |
| `- item\n\n    {% include "real.md" %}` | protected | list paragraph — include dropped |
| `Intro\n\n\t{% include "gone.md" %}` | reference | code — load NotFound |
| `` \`{% include "real.md" %}\` `` | protected | text — include dropped |
| ```` ``` ```` … ````` ```` ````` then an include (G17) | protected | the longer closer closes — dropped |

`separate_statements`: a longer fence closer didn't close (statements
after it merged into one `<p>`), and `Hello {# c #} {% if a %}\nShown`
split the paragraph in two (G18).

## Root cause and fix
Both scanners re-implemented CommonMark's block structure by hand
(fences, indentation, backtick runs) and each patch (G13's included)
added its own disagreements. Fix: pulldown decides. `code_ranges` takes
the byte ranges of `Event::Code` and code blocks from pulldown's offset
iterator with the conversion's own options. `separate_statements` skips
statements inside the original source's code (separation inserts blank
lines only around whole lines outside code, so it can't move code) and
measures a statement's line from the last newline before it, so an
inline statement earlier on the line counts (G18). `resolve_references`
protects the ranges of the text the conversion actually parses
(`template_code_ranges`: the separated text, mapped back through the
inserted newlines — separation can turn an indented line into a code
block). Raw blocks, comments and expressions keep their Tera handling.
