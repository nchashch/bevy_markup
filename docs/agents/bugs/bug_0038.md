## Symptoms

An `<input>` kept by an update ignored everything that changed around it:
a re-render with a new `value` attribute didn't change the field, restyles
(theme swap, `:focus`/`:hover`) left stale `TextFont`/`TextColor`, and a
changed `name` was ignored (so the form payload key went stale).
`update_spec` also inserted `EmSize` where `spawn_spec` deliberately
doesn't.

## Root cause

`update_spec` never handled `spec.text_input` — the kept-field path had
no arm for it.

## Fix

`update_spec` updates a kept input: the cascade's font/color, the
`InputName`, and the text — only when the `value` attribute it was built
from changed (the typed text is app state, tracked by `InputValue`);
widget components are removed when the element stops being a field, and
`EmSize` is no longer inserted on inputs (`bbd0959`).

## Also (same review, retracted docs)

`maxlength` and `placeholder` were documented as carried over (ADR 0016
Decision 1 mentioned `maxlength` → `max_characters`) but were never read;
Bevy 0.20's widget has neither. The docs (lib.rs, AGENTS.md, the
`text_input_element_maps_to_the_widget` comment) stop claiming them.
