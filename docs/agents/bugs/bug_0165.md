## Root cause and fix
`CursorFrame` holds `Cell`s and derived `Clone`. The nested container's
y computation worked on a clone, so the `valid.set(false)` for a child
without a height landed on the copy: the frame stayed valid, the cursor
skipped the unknown height and the siblings after it culled at wrong
positions. The root frame indexed the real frame and was unaffected.
Fix: borrow the frame; `CursorFrame` is no longer `Clone`, so a write
can't land on a copy again.
