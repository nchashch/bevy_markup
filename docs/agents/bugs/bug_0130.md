# bug_0130 - `+` matched the farthest preceding sibling instead of the adjacent one

| field | value |
|---|---|
| ID | bug_0130 |
| Status | **fixed** (this session, uncommitted at discovery) |
| Severity | medium (wrong styling on any `.a + b` selector with several preceding siblings) |
| Component | src/cascade.rs (sibling combinator matching) |
| Discovered by | browser oracle (`browser_oracle` test, new `sibling_combinators` vector) |
| Discovery agent | omp session, `opencode-zen/glm-5.3-flash` |
| Commit at discovery | `b69b95e` |
| Date | 2026-10-15 |
| Regression coverage | `sibling_combinators_vector` (oracle-checked), `cascade::tests::sibling_combinators_match_preceding_siblings` (non-adjacent case) |

## Symptoms and repro

`.hot + p` went green on *every* `p` after a `.hot` element with any
preceding sibling, not just the immediately following one:

```html
<div class="hot">hot</div>
<p class="after-hot">after hot</p>
<p class="far-after">far after</p>
```

With `.hot + p { color: #00ff00 }`, `far-after` rendered green; CSS says
white (only `after-hot` is adjacent). `~` was unaffected (it scans all
preceding siblings anyway).

## Root cause

`ElementState::previous_siblings` is built in DOM order — farthest
first, the **last** entry being the immediately preceding sibling — but
the `AdjacentSibling` arm (and the reactivity record's mirror of it)
read `siblings.first()` (the farthest). The field's doc comment said
"nearest first" while the match arm's comment claimed the opposite: the
two comments contradicted each other and the code followed neither. The
cascade unit test fed the list in the match arm's assumed order (nearest
first), so it passed — the oracle, running the real pipeline, caught it.

## Fix

`+` reads `siblings.last()` in both the match arm and
`matches_ignoring_pseudo`; both comments now say DOM order. The unit
test's list is in DOM order and gained the case the bug got past
(`.page + p` must not match when `.page` is not adjacent).

The `sibling_combinators` vector's expected dump had the bug baked in
(`far-after` green); corrected to white.
