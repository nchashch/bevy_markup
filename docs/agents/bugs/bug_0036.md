## Symptoms

Documents with a small dynamic part and a large static part (dynamic
header, static Markdown body) switched skeleton pairing off and never got
it back: every rebuild collected the whole document again.

## Root cause

The usefulness gate compared collection work, but counted a reused
subtree as 1 while counting every node inside it when collected — the
score compared 1 against `n`, so any large reused subtree looked useless.

## Fix

A fresh spec counts itself plus its children; a reused (cached) subtree
counts once — its nodes were neither cascaded nor re-collected
(`0ede9b6`). The proptest that guards reuse (R01) no longer strips the
skeleton from the comparator, so it actually exercises reuse.
