# bug_0019 — A value-less attribute ate the next attribute's first character (upstream `tl`)

**Status:** fixed (`f81acce`) by switching the HTML parser to
`astral-tl` 0.8.0. **Severity:** high — `<div autofocus data-on-click="x">`
silently lost its click hook, so the element was neither clickable nor
focusable; any boolean HTML attribute followed by another attribute is
affected.

**Component:** HTML parsing (upstream `tl` 0.7.8, UPSTREAM.md U11).

## Symptoms

prototype_19's main menu, after the browser-style focus work moved
`autofocus` from a class to the attribute: the Connect button
(`class="button primary" id="connect" autofocus data-on-click=…`) vanished
from the app's clickable list and focus started on the next button.

## Root cause

`tl::parser::base::parse_attributes` advances one byte after every attribute
to step over a quoted value's closing quote. For a value-less attribute
`parse_attribute` has already skipped the following whitespace, so the
advance consumes the next attribute's first byte: `autofocus` +
`ata-on-click="x"`. A standalone probe confirmed it on tl 0.7.8 (also across
a newline) and the correct parse on astral-tl 0.8.0.

## Fix

`Cargo.toml`: `tl = { package = "astral-tl", version = "0.8.0" }` —
astral-sh's maintained fork, same `tl` library name and API; the full test
suite passes unchanged.

## Regression test

`tests/html_ui.rs` `focus_navigation_scope_and_styles`: `#b` carries
`autofocus` before `data-on-click`; with `tl = "0.7.8"` restored the test
fails at the `autofocus` assertion (spot-checked), with astral-tl it passes.
