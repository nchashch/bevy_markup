## Symptoms

In `TestUi`:

- `#pt { font-size: 24pt; }` renders at `16px` (dropped; expected `32px`).
- `#in { font-size: 0.5in; }` renders at `16px` (dropped; expected `48px`).
- `#calc { font-size: calc(24pt); }` renders at `32px` (works inconsistently via `calc()`).
- `#off { outline: 2px solid red; outline-offset: 6pt; }` dumps as `outline=2,0,#ff0000` (offset dropped to `0px`; expected `8px`).

## Root cause

In ADR 0048's CSS parser, `length_unit` (`src/css/value.rs`) converts `in`, `cm`, `mm`, `Q`, `pt`, and `pc` into CSS pixels tagged `Unit::Abs` (distinct from `Unit::Px`). While `unit_val` (`src/css/value.rs:119`) and `letter_spacing` (`src/css/property.rs:1221`) handle `Unit::Px | Unit::Abs`, both `font_size` (`src/css/property.rs:1436`) and `outline-offset` (`src/css/property.rs:475`) match only `Lp::Dim(px, Unit::Px)` and fall through to the unsupported branch for `Unit::Abs`. `font-size: calc(24pt)` works only because `evaluate` folds it via `unit_val` into `Val::Px(32.0)`.

## Fix

Matched `Lp::Dim(px, Unit::Px | Unit::Abs)` in `font_size` and switched `outline-offset` to `parse_lp(input)?.px()` (handling `Unit::Px`, `Unit::Abs`, and folded absolute `calc()`). Audited `src/css/` for all other `Unit::Px` matches; none remained. Both unit and property tests failed before the fix and pass with it.
