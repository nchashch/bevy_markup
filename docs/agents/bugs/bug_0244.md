## Symptoms

The cargo-fuzz `html` target stopped at `out-of-memory
(malloc(4294967296))`. Its allocation stack ends in `write_node`, called
from `HtmlDocument::outline`. An app showing `HtmlDebugOutline` runs the
same code (`build.rs`).

The honggfuzz `html` jobs of 2026-11-19 and 2026-11-20 failed with "The
hosted runner lost communication with the server" about two minutes into
fuzzing and left no artifact. Honggfuzz had no memory limit. That these
two runs hit this input's path is inferred: their corpora were not
replayed. Under `--rlimit_as 4096` the crashing input aborts the pre-fix
build (42 crashes in 200 iterations, peak RSS 3.3 GB) and not the fixed
one (0 in 1,135, peak RSS 248 MB).

## Minimal reproduction

```rust
let document = HtmlDocument::parse("<b>".repeat(20_000)).unwrap();
document.outline(&LocalizedText::default()); // 400 MB
```

Unclosed tags nest, and each line holds two spaces per level, so `n` tags
make about `n²` bytes.

## Root cause

The outline wrote the full indent for every node with no limit on its
total size. Each stack entry also owned a copy of its indent, costing
depth × width while a wide element's children waited on the stack.

## Fix

`OutlineWriter` takes `MAX_OUTLINE_BYTES` (1 MiB), cutting at a character
boundary and failing the write; the walk stops and `outline` closes with
an "outline truncated" note. Stack entries carry the depth instead of the
indent text.

`scripts/fuzz-honggfuzz.sh` now passes `--rlimit_as 4096`, matching
cargo-fuzz's memory limit, so a future blowup is saved as a crash instead
of taking the runner down.
