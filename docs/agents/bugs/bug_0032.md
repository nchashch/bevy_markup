## Symptoms

Scenario (a): swapping `DefaultStylesheet` a.css → b.css and changing the
context in the same frame (the theme-button case) restyled only the
changing subtree — the static paragraphs kept the old color until
something else forced a restyle. Scenario (b): replacing a loaded sheet
with a missing one while the context changes — the failing sheet resolves
with no event, the retry build reuses, and the old styles stay.
Contradicted ADR 0021 ("stylesheet changes already force full rebuilds")
and the lib.rs docs.

## Root cause

`skeleton_eligible` checked state/vars/fonts/images but never
`own_changed`/`default_changed`, and a style change held back by a `Wait`
was merged into a later `Build` by `pending.take().max(change)`
(`rebuild.rs`), which looks content-only to the reuse gate.

## Fix

A style-side change observed but not yet applied is tracked as
`style_pending` (it survives being merged into a later `Build`, unlike
`pending`); the reuse gate refuses cached specs while it is set, and the
executed update clears it (`0ede9b6`, `RebuildState::style_pending` /
`style_pending_applied`).
