# bug_0017 — Restyle fallback rebuild despawned app-nested `HtmlUi`s (panic when they updated the same frame)

**Status:** fixed (`d079b08`). **Severity:** high — startup crash of the
demo (no input needed) once `:hover` styling landed.

**Component:** `src/build.rs` (`same_shape`).

## Symptoms

Same crash as [bug_0016](bug_0016.md) — `Entity despawned: The entity with ID
461v0 is invalid` from a queued `despawn_related::<Children>` — but through a
different route: an `HtmlUi` deciding **Restyle** whose `same_shape` check
failed fell back to the rebuild branch, and the fallback's recursive
`despawn_related` killed the app-nested `HtmlUi`s sitting in its subtree.
When a nested UI updated the same frame, its queued commands hit the
despawned entity and the app died. Deterministic at startup (the shell's
first `PseudoState` inserts + the content docs' first builds), and it also
meant every restyle of the shell destroyed and respawned the nested
documents.

## Root cause

`same_shape` compared the slot element's spec (no children) against the
entity (children = the app-nested `HtmlUi` roots) → mismatch → rebuild
fallback. Nested `HtmlUi` children are app-attached, not spec-owned, so they
must not count as a shape mismatch; restyles keep them, rebuilds replace
them wholesale.

## Discovery

- User ran the demo after the `:hover` work landed; it panicked ~25 ms after
  window creation, before any input. Agent: `zai/glm-5.3-flash:high`,
  2026-10-05. Traced with `bevy/debug` (names the failing command) +
  `bevy_markup=debug` decision logs: the shell decided `Restyle` while the
  outline docs decided `Build` — outside bug_0016's suppressor set (which
  only covers ancestors deciding `Build`), then the shell's restyle fell
  back to a rebuild.

## Fix

1. `Tree` (the `same_shape` query) gained `Has<HtmlUi>`; `same_shape` filters
   nested-`HtmlUi` children out before comparing — an app-nested UI root is
   not the spec's business.
2. The `:hover`/`:active` states walk (`build_html_ui`) skips nested-`HtmlUi`
   subtrees for the same reason their *handles* would pollute the state map:
   a nested UI's DOM handles index its own document. (The walk's starting
   entity is the UI root itself and is exempt.)

## Regression test

`tests/html_ui.rs` `restyle_with_nested_uis_keeps_them`: an outer `HtmlUi`
with a slot holding a nested one; hovering both in the same frame restyles
both in place — panicked with the fix removed (spot-checked), now asserts
both dumps and that the nested entity survived.
